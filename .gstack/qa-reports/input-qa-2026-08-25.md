## Temuan

### BUG-B (FIXED, medium-high) — blind-count barcode tidak tersimpan
- **Lokasi**: `app/Models/StockOpnameItem.php` line 15 (`$fillable`), dipakai oleh `app/Http/Controllers/Api/StockOpnameApiController.php:178`
- **Gejala**: `StockOpnameItem::updateOrCreate([... 'barcode_raw' => $request->barcode_raw ...])` meneruskan barcode yang dipindai pada saat stock opname **blind count** (part tak dikenal), tapi `$fillable` model tidak memuat `barcode_raw` → nilai **diam-diam di-drop**, tidak pernah tersimpan.
- **Bukti**: kolom `barcode_raw` ADA di DB (migrasi `2026_02_04_132352_modify_stock_opname_items_for_blind_count.php`), tetapi `(new StockOpnameItem)->isFillable('barcode_raw')` = **false**.
- **Fix**: tambah `'barcode_raw'` ke `$fillable` (setelah `gci_part_id`).
- **Sebelum/Sesudah**: `isFillable` false → true; regression test create→find memastikan `barcode_raw` tersimpan.
- **Regression test**: `tests/Feature/StockOpnameFillableRegressionTest.php` — PASS (2 tests, 4 assertions).
- **Commit**: `79fbcc7` (fix), `8c09620` (test):
  - `fix(qa): StockOpnameItem fillable barcode_raw - blind-count barcode silently dropped`
  - `test(qa): regression test for StockOpnameItem barcode_raw data-loss`

### BUG-C (DEFERRED, low / latent) — legacy Arrival drop status
- **Lokasi**: `app/Models/Arrival.php` (`$fillable` 30 kolom, tanpa `status`), dipakai umum oleh controller legacy (mis. `Purchasing/PurchaseOrderController.php:209` → `\App\Models\Arrival::create(['status' => 'pending', ...])`)
- **Gejala**: `status` di-submit tapi legacy `Arrival::$fillable` tidak memuatnya → **di-drop**. Saat ini tak terlihat karena kolom `arrivals.status` ber-default `'pending'` (migrasi `2025_01_01_000200_create_arrivals_tables.php`), jadi hasil kebetulan benar. Namun **latent**: jika intent status ≠ default (mis. `draft`), nilai hilang & arrival tampil di state salah.
- **Catatan**: `NewSchema\Incoming\IncomingArrival` SUDAH punya `status` di fillable — inkonsistensi legacy vs new-schema.
- **Alasan defer**: bersifat low severity (perilaku saat ini benar) DAN file `Arrival.php` punya WIP concurrency `generateArrivalNo()` yang belum di-commit — memaksa fix di sini akan membundel perubahan WIP (mengganggu atomisitas commit).
- **Rekomendasi follow-up**: tambahkan `'status'` ke `Arrival::$fillable` setelah file WIP selesai & di-commit, lalu tambahkan regression test (mirror pola GciPart/StockOpname).

### FALSE POSITIVES (diverifikasi, TIDAK ada bug)

- `ProductionOrder/ProductionInspection/ProductionOrderActivity/ProductionMaterialRequest/ProductionDowntime` (legacy) — pakai `$guarded = ['id']` (allow-all), tidak ada silent-drop.
- `ProductionGciApiController` QDC/downtime — payload panjang masuk ke kolom `notes` (JSON-encode), bukan sebagai fillable attr.
- `SubcountApiController` — `$request->all()` disimpan sebagai nilai `raw_payload`, bukan mass-assignment create arg.

- `WarehouseLocation`, `OutgoingPo` — field yang di-submit semua ada di `$fillable` legacy.
